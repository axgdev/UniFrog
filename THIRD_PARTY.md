This is a license inventory and attribution aid, not legal advice.

## Source Layout Policy

- `src/third_party/` is for small source files intentionally vendored in this
  repository. Each vendored library must keep its upstream copyright/license
  notice in place and, when practical, include its license file in the same
  directory.
- `.deps/` is generated by `make deps` and contains pinned upstream checkouts.
  Do not commit `.deps`; update pins in `Makefile` or `cores/manifest.mk` and
  keep UniFrog changes as patches under `cores/patches/`.
- `unifrog-hcrtos-sdk/` is a submodule. It is a mixed-license SDK staging tree,
  not MIT-only code. See `unifrog-hcrtos-sdk/LICENSE` and
  `unifrog-hcrtos-sdk/THIRD_PARTY_NOTICES.md`.
- `build/`, `output/`, `cores/output/`, `frontend/output/`, and
  `js2300/output/` are generated artifacts and are not source of truth for
  license review.

## Binary Distribution Notes

Release SD-card archives include firmware, native modules, and libretro core
modules. The package installs this notice as `/unifrog/THIRD_PARTY.md` and the
project license as `/unifrog/LICENSE.txt`.

For GPL and other copyleft components, the corresponding source is the exact
UniFrog repository revision used for the build, plus the pinned upstream
checkouts reproduced by `make deps`. For SDK-linked binaries, also preserve the
SDK license and notice files and the build scripts needed to relink.
